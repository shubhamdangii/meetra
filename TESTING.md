## Findings (fixed in the repo)

BUG-1 and BUG-2 are fixed by migrations 20261128040000 and 20261128050000 (applied to live on 2026-11-28). BUG-3 is fixed in EventPage.tsx. Their tests above now pass. Original reports:

- **BUG-1 (REAL BUG)**: No host or admin can save an event: database error 'null value in column maps_url of relation event_locations violates not-null constraint'. save_event_location inserts a row with only plan_id, but event_locations.maps_url is NOT NULL and no migration relaxes it. Fails even with a valid Maps link. Everything after it (approve, go live) cannot be reached from the UI. Check whether the original database was patched by hand (drift).
- **BUG-2 (REAL BUG)**: Admin dashboard lists an inactive event as 'Active' and counts it in 'Active events'. The Event library shows it under Inactive, so the two screens disagree.
- **BUG-3 (REAL BUG)**: A past real event never offers the next date. 'Next date' looks up events with the same key, but every real event has its own unique key (x<id>), so only the old sample plans could ever show it. Product decision needed.
